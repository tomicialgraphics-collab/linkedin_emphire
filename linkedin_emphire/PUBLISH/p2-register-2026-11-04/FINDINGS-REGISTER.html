Corrective action and acceptance criterion, per row

S1. Either make the two-append operation transactional, or give the reply an explicit uncertainty outcome that distinguishes "the acknowledgement failed" from "no bytes were persisted", because today the caller cannot tell those apart and the disk has bytes the reply denies. Accepts as closed when a regression mode produces a failed second append and the reply can only be read one way about what is durable; the mode fails on the current tree.

S2. Write a repair record naming the quarantined file and the byte range on the runtime cut path, with the same provenance the start-up repair already writes. Accepts as closed when a mode that cuts the tail mid-run finds a repair row naming the quarantined bytes, and the mode fails without it.

S3. Classify each mode before and after execution so an import failure is NOT-RUN and not MISSED, bound child execution with an explicit timeout classification, stream progress instead of buffering, and preflight optional tools so a missing bc is reported once rather than printed per row. Accepts as closed when an injected verify.py import failure reports NOT-RUN for the affected modes, and the mode fails against the current runner.

S4. Blocked on the environment, not on the code. Needs a filesystem that permits the immutable flag, or another way to establish the same condition, recorded with the run. Accepts as closed when the immutable condition is established and the verifier refuses to present the old report as fresh; until then this row stays open and must not be described as passing.

S5. Remove fixture trees on the way out, retaining them only when retention is asked for, and name what was retained in the output when it is. Accepts as closed when a mode run against a fresh TMPDIR leaves no hfb-f2* directory behind, and the mode fails when the fixture is leaked.

Priority agreed with the reviewer

S1 and S2 first, because both are integrity claims and both are cheap to state precisely. Then S3, which is runner reliability rather than benchmark correctness. S5 is housekeeping. S4 waits for the environment.
