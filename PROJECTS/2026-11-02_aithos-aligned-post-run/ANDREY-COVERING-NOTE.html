The line endings catch, 3 November

The manifest reported 540cf2abfa... for redteam.py and the package says 6048b70aadfe.... Both are correct. The published value is the SHA-256 of the file's canonical bytes with LF endings. The Windows checkout converts LF to CRLF, which adds 468 carriage returns and changes the digest.

Verified here by converting the same file both ways:

FormSHA-256
LF, as the repository stores it6048b70aadfe2750ff463d283b0fd34e92aee19999ee386a097e02b79bdf7581
CRLF, as a Windows checkout writes it540cf2abfa2643143d0c84b12c40d3e8f324a3bd6c84e5620124f8282049cff9

This is the single most likely thing to be mistaken for tampering in a provenance review, so it is disclosed in the covering note rather than left to be discovered. If it had been sent silently, an honest reviewer would have been right to stop reading.
