Worth adding the line from the changelog that will matter most later: this is version updates, not security updates. There's no advisory feed for a skill or an MCP server that changes behaviour badly, so the pull request arrives and the only thing checking the new version is whoever reads it. A package that breaks its own API usually fails loudly at the call site. A prompt or a tool schema shifts and just answers differently, with CI green on both sides. Lockfiles are necessary and not sufficient. Each primitive needs a behavioural check with a recorded baseline to diff against, because provenance says where a thing came from and nothing yet says it still does what last week's run proved.
