You are correct that a locally assigned action ID cannot independently establish that a missing action existed. The ID is minted on the host, so the name of the gap dies with the host that named it, and the audit system cannot distinguish an action that existed and was lost from an action that never was. The named gap requires the name to have been witnessed out of band. The fix is to move the minting authority. Option one: the audit system issues the ID range. The host requests an ID commitment before proposing the action, and the issuer's own record is the independent witness that an action with that ID was proposed; it requires no trust in the host. I would take option one as the default for high-consequence classes, and keep option two for classes where the round trip to the issuer is not affordable.
