## Comment, paste as is

You already ask for the refusal and for the trace. What makes either usable is the run beside it.

Run it as a pair and change one variable. Permission intact: the effect lands and the trace shows the state that was consulted. Permission revoked: the effect does not land and the trace shows the same check against the changed state. That record has to be written by the boundary doing the enforcing, not by the agent that requested the action, or the evidence comes from the party under test.

Without that, a system with no check in it passes. It refuses nothing, its trace is empty in the revoked case, and the allowed case was never measured.

A refusal on its own says an effect did not happen. It doesn't say anyone installed the brakes.

## Why this one

He asks for two things, a refusal and a trace that names the authority state, and both are one-sided. A system that never consults authority produces exactly the same pair: no effect, and no record of a check. As written, the test cannot separate a working stop from a missing one, which is the only distinction he actually cares about.

The addition is the control: the same action with the permission intact, run at the same moment, leaving the same kind of record. Then the refusal is attributable, because the two runs differ in one variable and nothing else. Authorship of the record is the other half. A trace written by the agent that wants to act is a statement from the party under test, so the enforcing boundary has to write it.

His own phrase comes back at the end. He finished on wanting to know whether anyone installed the brakes, and the point of the comment is that a single refusal cannot tell him.
