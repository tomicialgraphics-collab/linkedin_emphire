The six

1. Neil Sahota (IBM Master Inventor, UN AI advisor, UC Irvine), 96 words

Post: AI incident threshold as consequential capability rather than damage.

`` The threshold is right, and the hard part is that consequential capability is invisible by default. Nothing broke, so nothing generated an incident record, and the only artifact is whatever the system around the model happened to log before anyone thought to ask. That is the argument for recording what the model read, not only what it did. A capability nobody knew it had is precisely the thing that cannot be reconstructed after the fact, because nobody knew to look. Governing by capability means building the record before there is a question to answer with it. ``

2. Hamel Husain (Parlance Labs, formerly GitHub and Airbnb, author of Evals for AI Engineers), 107 words

Post: comment on Vik Paruchuri's OCR benchmark findings: scorer and spec defects.

``` Almost nothing in that list is a model problem. A wrong expected value, an unstated formatting requirement, a postprocessor worth more than the gaps between the models it ranks, a correct answer penalised for following the document.

Those are defects in the benchmark, and they are invisible from the score, because the score is what the defect produces.

The artifact I would ask any benchmark for is the one almost none of them publish: its own defect register, with the failing example and the date it was found. A published scorer plus a short list of known failures catches most of this before a leaderboard has to. ```

3. Rock Lambros (Zenity, OWASP Agentic Security Initiative core team, ACS project lead), 100 words

Post: OWASP ACS and the Guardian: no one verifies a self-declared conformance claim.

``` No one verifies a self-declared conformance claim is the sentence that decides whether ACS travels outside the room it was written in. A Guardian that logs an audit trail is necessary and not sufficient, because the log is produced by the thing being assessed.

The version that settles it is the one a buyer can run without you: a reference implementation, a fixed test set, and a failure that produces a document rather than a support ticket.

Publishing the Guardian limitations requirement by requirement is the part most standards skip, and it is the part a buyer will actually read. ```

4. Sarah Bird (Chief Product Officer of Responsible AI, Microsoft), 115 words

Post: GitHub AI application scanning, public preview, three AI-specific risks on the pull request.

``` The gate is the right place for the architecture question: can untrusted content reach a model that holds tools. That is decidable from the code path, and it is worth blocking a merge over.

What the code path cannot tell you is whether the model obeys the content once it arrives. That is a property of the run, so the pipeline finding and the runtime evidence have to point at the same span, or a closed alert and a fixed vulnerability look identical in the pull request.

Which is also how to judge a suggested fix. Encoding the untrusted input closes the finding. It does not change whether the model can be steered by it. ```

5. Allie K. Miller (2M followers, AI business voice, formerly Amazon and IBM), 94 words

Post: one agent writing a brief that a second agent executes overnight from the inbox.

``` Everyone here is right that the brief sets the ceiling. The floor is set by what the executor leaves behind.

Thirty items finished overnight is a claim until each one arrives with the artifact that proves it: the draft, the commit, the sent mail. A summary of what got done is the one thing you cannot check at 8am, because the same system that did the work wrote it.

So the handoff needs a second field beside priorities: for each item, what evidence would prove it. Then the morning is triage instead of audit. ```

6. Jerry Liu (co-founder and CEO, LlamaIndex), 81 words

Post: OCRia-1 serving: 285 to 2800 tokens per second on one B200.

``` The 10x changes the evaluation, not only the cost. At 2800 tokens per second you can afford invariance tests that used to be too expensive to run: the same page recompressed, rotated a degree, re-rendered at another DPI, parsed twice. Identical output every time is a real claim about the parser reading the document instead of the artifact.

A single score against a fixed transcript cannot see that class of failure. Cheap inference is what makes the test that can affordable. ```
