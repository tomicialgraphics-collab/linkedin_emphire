# 00 START

The boot contract. One page. Read it before the second page of anything.

This repo is not a folder of drafts. It is a pipeline with seven stages, one gate, and a written
record of every file that left it. A session that skips the pipeline produces work the owner cannot
use, and the owner has paid for that mistake more than once.

---

## 1. The order, and why it is that order

| # | Read | Because |
|---|---|---|
| 1 | this file | to know the order |
| 2 | `PIPELINE/20-RULES.md` | the rules are the client. 30 of them, and 20 are blocking |
| 3 | `PIPELINE/50-CONTRACT.md` | what shape the artefact has to be in |
| 4 | `PIPELINE/10-STAGES.md` | which stage the work is in, and what closes it |
| 5 | `PIPELINE/30-TEMPLATES.md` and `DAILY CONTENT/visual_and_hook_spec.md` | if the deliverable is a post |
| 6 | `PIPELINE/40-HASHTAGS.md` | if the deliverable is a post |
| 7 | `context.md` section 7 and section 8 | standing rules and voice, in the owner's words |
| 8 | `STATE/OPEN-LOOPS.md` | what is unfinished and who is waiting |

Run `python3 linkedin_emphire/TOOLING/pipeline.py start` and it prints this list, the rule counts and
the open loops, so a session cannot claim it did not know.

## 2. The five things that are never negotiable

1. **No em dashes.** Not in a post, not in a comment, not in a review, not in a session log.
2. **No word from `DAILY CONTENT/banned_words.txt`.** On LinkedIn the list is literal.
3. **No `tomicial` identity outward.** No repo URL, no handle, no email variant, in anything a
   client, reviewer, hiring team or vendor sees. Files plus SHA-256, never a link.
4. **No fabricated number.** If there is no run, ship the method and say there is no run.
5. **The owner sends. The agent drafts, gates and hands over.**

## 3. The gate

```bash
python3 linkedin_emphire/TOOLING/pipeline.py check <path>
```

Exit 0 means no blocking rule fired. It does not mean the piece is good, and it does not mean the
manual rules were done. Those are listed at the bottom of `20-RULES.md` and they are the ones that
get checked by a person who is prepared to be honest.

A blocked file does not get sent with the block explained in the chat. It gets fixed and re-gated.

## 4. The delivery record

```bash
python3 linkedin_emphire/TOOLING/pipeline.py log <path> --to "Marvin" --how "Drive link, hash in message"
```

This hashes the file, runs the gate, and writes the row into `STATE/DELIVERY-LOG.md`. If the file is
not in that table, it did not go anywhere, whatever the conversation says afterwards.

## 5. Where things live

`MAP.md` is the index of the whole tree, regenerated by `pipeline.py map`. Every area has a declared
purpose, an owner role and a stage. If you add a folder, declare it in
`PIPELINE/registry/areas.json` in the same commit, or `map` will call it undeclared.

## 6. The one thing the pipeline cannot do

It cannot read the room. It cannot tell whether the argument is worth a stranger's time, whether the
profile read was real, or whether the boxed phrase would work on someone else's post. Those are
marked `manual` on purpose. The gate catches the rules a careful reader forgets. It does not replace
the careful reader.
